# AA.Annotate v0.5.0

Linux desktop support, cross-platform toolbar reliability, and interaction-readability
release.

## Added

- Added Linux x64 support with direct X11 capture and XDG Screenshot portal capture on
  Wayland.
- Added Linux platform services, session detection, X11 window integration, portal
  request handling, and platform-specific smoke tests.
- Added a self-contained Linux release archive with user-scoped install/uninstall scripts,
  executable-mode validation, bundled CLI, and bundled Codex skill.
- Added Linux packaging and testing to the tagged GitHub release workflow. Releases now
  publish Windows and Linux x64 assets together.
- Added restrictive per-user Linux runtime/session paths and atomic private-file writes.
- Added a shared cross-platform interaction palette with automated contrast and state
  tests.
- Added explicit capture-quality presentation policy tests.
- Added Linux installation, native dependency, portal, source-build, and troubleshooting
  documentation.

## Changed

- Start the toolbar at the top center of the display on the first run.
- Keep separate permanently owned passive and embedded toolbar surfaces and synchronize
  their state instead of moving one Avalonia control between top-level windows.
- Keep the editing toolbar embedded above the active capture surface while preserving a
  detached topmost toolbar in passive mode.
- Show the capture-quality selector only while a current capture is active; hide it in
  passive mode and when no capture exists.
- Make toolbar colors application-owned so Windows, GNOME, and KDE theme defaults cannot
  make icons or text unreadable.
- Give crop, privacy mask, annotation, capture selectors, dropdown items, comment-editor
  actions, and destructive controls distinct hover and pressed states.
- Use a dark completion-button surface with a visible green foreground, including hover
  and pressed states.
- Bind toolbar and delete icons to their parent button foreground so runtime state changes
  are reflected consistently.
- Normalize the product name to `AA.Annotate` across UI titles, prompts, installers,
  plugin metadata, documentation, and release surfaces.
- Update the bundled skill with Linux executable resolution, graphical-session, portal,
  dependency, and privacy-boundary guidance.

## Fixed

- Fixed missing or dark icon foregrounds in capture/new-capture controls and dynamic
  capture/display dropdown items.
- Fixed annotation-comment and privacy-mask delete icons and their danger hover states.
- Fixed Avalonia host-theme pseudo states overriding the intended foreground and hover
  palette.
- Fixed GNOME crashes caused by reparenting a live toolbar across different Avalonia
  layout managers.
- Fixed active overlay modes covering the toolbar during crop, annotation, and privacy
  mask workflows.
- Fixed stale capture-quality UI remaining visible after returning to passive mode.
- Fixed Linux session-state writes so a delayed activity update cannot overwrite a
  completed session result.
- Fixed Linux CLI/app path resolution and executable validation for installed bundles.
- Preserved Windows capture and window-integration behavior while sharing the new toolbar
  presentation and palette rules.

## Linux requirements

The GitHub Linux archive is self-contained and does not require a separate .NET runtime.
It still requires the desktop's native X11/font libraries. Wayland additionally requires
XWayland, `xdg-desktop-portal`, and the portal backend matching GNOME or KDE. Building from
source requires the .NET 10 SDK. See
[Linux installation and requirements](../linux.md) for commands and troubleshooting.

- Windows host: all App, Core, CLI, and Linux-platform test projects passed

- GNOME VM: Ubuntu 24.04.4 local Wayland session; App tests and Linux publish passed, with
